## Pattern Preserved

Each module entry originally followed this structure:

1. scope and responsibility
2. relevant interfaces or screens
3. internal services/routines
4. supported operational concepts
5. not-confirmed caveats
6. mapping implications for AS IS / TO BE work

## Redaction Boundary

Concrete module names, routine names, source paths, integration partners, and product-specific sequencing are intentionally replaced with placeholders.
